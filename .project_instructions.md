## WellnessLog.in (formerly Amma's Health Logger)

### Project Overview
A conversational health logging chatbot for tracking a single patient's (Amma) daily health maintenance — blood pressure readings, medications, symptoms, observations, and doctor visits. Private app used by the patient and 2-3 family members, all healthcare professionals. No HIPAA/medical disclaimers needed.

### Technical Approach
- Database: PostgreSQL with Prisma ORM
- LLM-powered chatbot for natural language health data extraction
- Structured data extraction via `<health_data>` JSON tags in LLM responses
- Email notifications via Abacus AI notification API (daily health summaries)
- Charts via Recharts library

### Key Design Decisions
- Shared access — no individual user accounts
- AI assistant persona: cheery, compassionate medical professional
- **Ayurveda expertise**: Assistant has deep knowledge of Ayurveda, Veda, Vedanta, and Yoga traditions. Does NOT volunteer this — only responds authoritatively when Amma or family brings it up. References classical texts (Charaka Samhita, Sushruta Samhita, etc.) and uses correct Sanskrit terminology.
- Amma prefers Ayurvedic approaches but has accepted allopathic meds for now — assistant respects both systems
- Data imported from original Health Log.md file (May 2026 data)
- Rebranded from "Health Logger" to "WellnessLog.in" (May 2026)
- Domain: wellnesslog.in (Hostinger)
- LLM: Ollama Cloud (gemma4:31b-cloud with vision)
- Email: Nodemailer SMTP (planned: update@wellnesslog.in via Hostinger)
- GitHub: https://github.com/vikram11/wellnesslogin (main + hostinger branches)
- SMS/Twilio integration deferred for future implementation

### App Structure
- **Chat tab**: Main conversational interface for logging health data
- **Reports tab**: BP trend charts, statistics, doctor-ready summaries (LLM-generated)
- **History tab**: Filterable tables for BP readings, Meds Taken (checklist showing taken/skipped meds per time slot), and Notes (freeform daily notes for symptoms, activities, events). Observations subtab was removed and replaced with Meds Taken.

### Data Model Notes
- **Observations** model still exists in DB for legacy data but is no longer actively used. The system prompt directs the LLM to use `daily_notes` for all non-BP, non-medication data.
- **MedicationLog** stores which meds were taken per time slot. The `/api/meds-taken` route enriches logs by cross-referencing with the Medication schedule to build a checklist.
- Chat history is cleared when system prompt changes significantly to avoid stale context.
- **Medications tab**: AM/MID/PM schedule with active/discontinued tracking
- **Email tab**: Send health summaries to any email address

### Visual Style
- Warm teal medical theme
- DM Sans / Plus Jakarta Sans / JetBrains Mono fonts
- Light/dark mode support
- Mobile-responsive with bottom tab navigation on mobile
- **Senior-friendly font sizes**: Chat bubbles use text-lg/text-xl, markdown content inherits that size, headings go up to text-2xl. Nav tabs use text-base (desktop) and text-sm (mobile). Input textarea is text-lg. Designed for readability without reading glasses.

### Push Notifications & PWA
- Web Push Notifications via VAPID/web-push library
- Service Worker at `/public/sw.js` handles push events and shows native notifications
- PWA manifest at `/public/manifest.json` — app is "Add to Home Screen" capable
- Icons: `icon-192.png` and `icon-512.png` (teal heart logo)
- API routes: `/api/push/subscribe`, `/api/push/unsubscribe`, `/api/push/send`
- `PushSubscription` model in Prisma stores endpoint, p256dh, auth, label
- `NotificationToggle` component in app-shell header (bell icon)
- 3 scheduled daemon tasks send push reminders: AM (8:00), MID (1:00 PM), PM (8:00 PM) Central
- **Important**: Push notifications require the app to be deployed to a public URL. Scheduled tasks use the deployed URL to POST to `/api/push/send`.

### Email Recipients
- `SavedRecipient` model stores email addresses as chips
- Email panel auto-saves entered recipients and shows them as removable chips
- Multi-recipient support (sends separate emails to each)

### User Preferences
- User wants simple, practical reports (BP trends, daily summaries)
- No legalistic medical disclaimers
- Free-form, conversational interaction style
- Ability to correct/edit logged entries conversationally
- User acknowledged iOS push requires Add to Home Screen (will help Amma set up)
- User is the brother (not sister) — building for Amma and his sister
- Voice chat (STT/TTS) and Tamil bilingual features were added then reverted (deemed overkill / not functioning in iframe). English-only going forward.
- **LLM Provider**: Switched from Abacus AI to **Ollama Cloud** (`https://ollama.com/v1/chat/completions`) using `gemma4:31b-cloud` model. Env var: `OLLAMA_API_KEY`. Both chat and doctor-summary routes use this.
- **Image Capture / Vision**: ChatPanel has image upload (gallery) + camera capture buttons. Images are compressed client-side (max 1024px, JPEG 0.7 quality). On send, images are first uploaded to `/api/upload-image` which saves them to `uploads/chat-images/` folder on disk and returns a persistent file path (e.g., `/api/uploads/chat-images/1716345678-abc123.jpg`). This path is stored in `ChatMessage.imageData` for both user and assistant messages (the assistant's imageData references the same image it analyzed). Base64 is still sent to the LLM for vision. The `/api/uploads/[...path]` route serves images from disk. Legacy base64 data URLs in older messages are still supported for display. On the VPS, the `uploads/` directory should be a Docker volume for persistence. System prompt instructs the LLM to analyze prescription bottles, lab reports, BP monitors, etc.
- **Email**: Switched from Abacus notification API to **Nodemailer** + SMTP. Env vars: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_FROM`. Works with Gmail App Password, Hostinger email, or any SMTP.
- **Platform cleanup**: Removed `appllm-lib.js` script tag from layout.tsx. Zero Abacus references remain in app code. Stale env vars (ABACUSAI_API_KEY, WEB_APP_ID, NOTIF_ID) still in .env for current hosting but excluded from tarball.
- **Self-Hosting Guide**: `SELF_HOSTING_GUIDE.md` at project root covers Hostinger VPS deployment. All code is VPS-ready. Remaining VPS-side tasks: Prisma output path fix, next.config.js simplify, crontab for push reminders, VAPID key regeneration.
